# Plan: Migration Framework

> **Usage note:** This plan was generated by an agent for review and execution. All tasks have explicit file paths and named functions. No step requires human interpretation at execution time.

## Summary

Repositories today have isolated migration commands (`repo migrate-identity`, `repo upgrade`, `migrate packet`) with no shared model: a caller must already know a migration exists **and** guess whether the repo needs it. The web UI cannot offer upgrades — it can only hard-code a list and run them blind. This plan builds a **migration framework** in `srs-repository`: a static, compile-time registry of migrations, each with a stable `id`, a per-repo applicability detector (`NotApplicable | Needed | AlreadyApplied`), and an apply function. It exposes the registry through a new `srs repo migrations` CLI command, a `srs repo migration-apply --id` CLI command, and two WASM bindings (`availableMigrations()` / `applyMigrationById(id)`). `migrate_identity` is registered as the first real migration (id `"migrate-identity"`). Delivering this now unblocks srs-web#190 (offer upgrades in the UI) with no web-side changes needed when future migrations are added.

## Contracts

### CLI output contract (ADR-011)

This plan adds **three new payload structs** to `crates/srs-cli/src/payload.rs`:

```rust
/// One migration in the registry, annotated with its per-repo status.
#[derive(Debug, Serialize, JsonSchema)]
#[serde(rename_all = "camelCase")]
pub struct MigrationEntryPayload {
    pub id: String,
    pub title: String,
    pub description: String,
    pub status: String,   // "notApplicable" | "needed" | "alreadyApplied"
}

/// Payload for `srs repo migrations`.
#[derive(Debug, Serialize, JsonSchema)]
#[serde(rename_all = "camelCase")]
pub struct RepoMigrationsPayload {
    pub migrations: Vec<MigrationEntryPayload>,
}

/// Payload for `srs repo migration-apply --id <id>`.
#[derive(Debug, Serialize, JsonSchema)]
#[serde(rename_all = "camelCase")]
pub struct RepoMigrationApplyPayload {
    pub id: String,
    #[schemars(with = "serde_json::Value")]
    pub result: serde_json::Value,
}
```

Run `cargo run --bin generate-schemas` after adding these. The new golden files
`crates/srs-cli/schemas/payload/MigrationEntryPayload.json`,
`RepoMigrationsPayload.json`, and `RepoMigrationApplyPayload.json` must be committed.

Verification: `cargo test --test payload_contracts` must pass.

No changes to `srs/docs/schema/2.0/` entity schemas. `bash scripts/check-schema-sync.sh` is expected to pass unchanged.

### Phase 1: Migration service

**Agent:** Repository Service Worker

#### Tasks

- [ ] Create `crates/srs-repository/src/migration_service.rs`
- [ ] Define `MigrationStatus` enum:

- [ ] Define `MigrationEntry` output struct:
  ```rust

  #[serde(rename_all = "camelCase")]
  pub struct MigrationEntry {
      pub id: String,
      pub title: String,
      pub description: String,
      pub status: MigrationStatus,
  }
  ```
- [ ] Define private `MigrationRegistryEntry` struct:
  ```rust
  struct MigrationRegistryEntry {
      id: &'static str,
      title: &'static str,
      description: &'static str,
      detect: fn(&dyn RepositoryStore) -> Result<MigrationStatus, RepositoryError>,
      apply: fn(&dyn RepositoryStore) -> Result<serde_json::Value, RepositoryError>,
  }
  ```
- [ ] Implement `fn detect_identity_migration(store: &dyn RepositoryStore) -> Result<MigrationStatus, RepositoryError>`:
  - Load manifest via `store.load_manifest()`
  - If `manifest.container` is `None` → return `Ok(MigrationStatus::NotApplicable)`
  - Let `mc = manifest.container.unwrap()`
  - If `mc.identity_instance_id` is `Some(id)`:
    - Find the entry in `manifest.instance_index` by id
    - If entry is `None` → return `Ok(MigrationStatus::Needed)` (pointer exists but target missing — migration should run to create a fresh purpose record)
    - If `entry.tier() == 2`:
      - Load `store.load_instance_json(entry.path())?`
      - If `typeNamespace == core_purpose::PURPOSE_TYPE_NAMESPACE && typeName == core_purpose::PURPOSE_TYPE_NAME` → return `Ok(MigrationStatus::AlreadyApplied)`
    - Return `Ok(MigrationStatus::Needed)`
  - Else (`identity_instance_id` is `None`):
    - If `mc.title` is non-empty OR `mc.description` is `Some(d)` with non-empty content → return `Ok(MigrationStatus::Needed)`
    - Else → return `Ok(MigrationStatus::NotApplicable)`
- [ ] Implement `fn apply_identity_migration(store: &dyn RepositoryStore) -> Result<serde_json::Value, RepositoryError>`:
  - Call `migrate_identity_service::migrate_identity(store)?`
  - Serialize result with `serde_json::to_value(result).map_err(|e| RepositoryError::Serialize { path: std::path::PathBuf::from("<migration-result>"), source: e })?`
  - Return the `serde_json::Value`
- [ ] Define static registry (after the two fn implementations above):
  ```rust
  static MIGRATIONS: &[MigrationRegistryEntry] = &[
      MigrationRegistryEntry {
          id: "migrate-identity",
          title: "Graduate identity to purpose record",
          description: "Converts a Tier-0 note identity (or a container with no identity \
                        pointer) to a com.semanticops.core/purpose Tier-2 Record.",
          detect: detect_identity_migration,
          apply: apply_identity_migration,
      },
  ];
  ```
- [ ] Implement `pub fn list_migrations(store: &dyn RepositoryStore) -> Result<Vec<MigrationEntry>, RepositoryError>`:
  ```rust
  pub fn list_migrations(store: &dyn RepositoryStore) -> Result<Vec<MigrationEntry>, RepositoryError> {
      MIGRATIONS.iter().map(|m| {
          let status = (m.detect)(store)?;
          Ok(MigrationEntry {
              id: m.id.to_string(),
              title: m.title.to_string(),
              description: m.description.to_string(),
              status,
          })
      }).collect()
  }
  ```
- [ ] Implement `pub fn apply_migration_by_id(store: &dyn RepositoryStore, id: &str) -> Result<serde_json::Value, RepositoryError>`:
  ```rust
  pub fn apply_migration_by_id(store: &dyn RepositoryStore, id: &str) -> Result<serde_json::Value, RepositoryError> {
      let entry = MIGRATIONS.iter().find(|m| m.id == id).ok_or_else(|| RepositoryError::InvalidInput {
          message: format!("unknown migration id: {id}"),
      })?;
      (entry.apply)(store)
  }
  ```
- [ ] Export from `crates/srs-repository/src/lib.rs`:
  ```rust
  pub use migration_service::{apply_migration_by_id, list_migrations, MigrationEntry, MigrationStatus};
  ```
  And declare the module: `pub mod migration_service;`
- [ ] Write tests in a `#[cfg(test)] mod tests` block at the bottom of `migration_service.rs` (all MemoryStore):
  - `list_migrations_returns_one_entry` — call `list_migrations` on a default MemoryStore, assert result has len 1 and `result[0].id == "migrate-identity"`
  - `detect_needed_for_note_identity` — use `make_store_with_identity` pattern from `migrate_identity_service.rs` tests; assert status == `Needed`
  - `detect_already_applied_after_migration` — run `migrate_identity_service::migrate_identity` first, then `list_migrations`; assert status == `AlreadyApplied`
  - `detect_not_applicable_for_no_container` — use `MemoryStore::uninitialized()` (no container set); assert status == `NotApplicable`
  - `detect_needed_for_no_identity_with_title` — store with container that has a title but `identity_instance_id: None`; assert status == `Needed`
  - `detect_not_applicable_for_no_title_no_description_no_identity` — store with container, empty title, no description, no identity; assert status == `NotApplicable`
  - `apply_by_id_migrate_identity_succeeds` — store with note identity; call `apply_migration_by_id(store, "migrate-identity")`; assert `Ok`, then assert `list_migrations` returns `AlreadyApplied`
  - `apply_by_id_unknown_id_errors` — call `apply_migration_by_id(store, "nonexistent")`; assert `Err(RepositoryError::InvalidInput { .. })` with message containing "unknown migration id"

- [ ] In `crates/srs-cli/src/commands/repo.rs`:
  - Add `use srs_repository::migration_service;` import
  - Add to the `use crate::payload::...` import block: `RepoMigrationApplyPayload, RepoMigrationsPayload, MigrationEntryPayload`
  - Add dispatch arms to `pub fn dispatch()`:
    ```rust
    RepoCommand::Migrations => cmd_repo_migrations(ctx),
    RepoCommand::MigrationApply { id } => cmd_repo_migration_apply(ctx, id),
    ```
  - Implement handlers:
    ```rust
    fn cmd_repo_migrations(ctx: CliContext) -> Result<String> {
        let migrations = with_store(&ctx, |store| {
            migration_service::list_migrations(store).map_err(anyhow::Error::from)
        })?;
        output::serialize(
            "repo migrations",
            RepoMigrationsPayload {
                migrations: migrations
                    .into_iter()
                    .map(|m| MigrationEntryPayload {
                        id: m.id,
                        title: m.title,
                        description: m.description,
                        status: serde_json::to_value(&m.status)
                            .unwrap_or_default()
                            .as_str()
                            .unwrap_or("unknown")
                            .to_string(),
                    })
                    .collect(),
            },
        )
    }

    fn cmd_repo_migration_apply(ctx: CliContext, id: String) -> Result<String> {
        let result = with_store(&ctx, |store| {
            migration_service::apply_migration_by_id(store, &id)
                .map_err(anyhow::Error::from)
        })?;
        output::serialize(
            "repo migration-apply",
            RepoMigrationApplyPayload { id, result },
        )
    }
    ```

  ```rust
  /// Return all registered migrations annotated with their per-repo applicability status.
  /// Returns a JSON array of `{ id, title, description, status }` objects.
  /// `status` is one of `"notApplicable"`, `"needed"`, `"alreadyApplied"`.
  pub fn available_migrations(&self) -> Result<JsValue, JsValue> {
      let result = migration_service::list_migrations(&self.store).map_err(js_err)?;
      to_js(&result)
  }

  /// Apply a registered migration by its stable id.
  /// Returns the migration-specific result as a JS value, or a JS error if the id
  /// is unknown or the migration cannot be applied.
  pub fn apply_migration_by_id(&self, id: &str) -> Result<JsValue, JsValue> {
      let result =
          migration_service::apply_migration_by_id(&self.store, id).map_err(js_err)?;
      to_js(&result)
  }
  ```

## Assumptions

- `detect_identity_migration` is pure-read (no writes, no side effects). Safe to call repeatedly.
- `MigrationStatus` serializes via `#[serde(rename_all = "camelCase")]` → `"notApplicable"`, `"needed"`, `"alreadyApplied"`. The CLI payload converts to `String` via `serde_json::to_value(&m.status)` to avoid pulling `Serialize` into schemars scope.
- The static registry `MIGRATIONS: &[MigrationRegistryEntry]` does not require `Send + Sync` beyond what bare fn pointers already provide.
- `srs-bindings` can call `migration_service` functions without WASM target issues: the service module uses only `dyn RepositoryStore` and `serde_json`, not `std::fs`.
- `MemoryStore::default()` and `MemoryStore::uninitialized()` (as used in `migrate_identity_service` tests) are the correct test doubles for the new tests.
