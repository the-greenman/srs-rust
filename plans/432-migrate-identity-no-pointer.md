# Plan: Migrate existing repos: root_note_id → identity_instance_id in serialized output history

> Issue: srs-rust#432

## Summary

Repositories created before #424 have no `identityInstanceId` in `manifest.container` and may lack a `com.semanticops.core/purpose` record. The existing `srs repo migrate-identity` command handles repos whose `identityInstanceId` points to a Tier-0 note, but errors with "identityInstanceId is not set" for pre-#424 repos that have no pointer at all. This plan extends the service to handle the `identityInstanceId = None` case by deriving the purpose record from the container's `title`/`description` fields. It also fixes structural debt: the six `com.semanticops.core/purpose` constants were duplicated across two files with inconsistent values (`fc…` vs `3b…`) — the canonical values from `srs/srs/package/core/` are the `3b…` variants. Phase 1 consolidates constants into a shared `pub(crate)` module and extracts a shared record builder; Phase 2 adds the None-branch to `migrate_identity`.

### Phase 2: Extend migrate_identity for identityInstanceId = None

**Goal:** `migrate_identity` creates a purpose record and sets `identityInstanceId` when the container has none, using container title/description as input. `MigrateIdentityResult` uses Option fields.

**Agent:** Repository Service Worker

#### Tasks

- [ ] In `crates/srs-repository/src/migrate_identity_service.rs`:
  - Remove the test `migrate_errors_if_no_identity_pointer` (lines 484-498 in current file) — the None case now succeeds.
  - Change `MigrateIdentityResult`:
    - `old_identity_id: String` → `pub old_identity_id: Option<String>`
    - `old_identity_tier: u8` → `pub old_identity_tier: Option<u8>`
  - Update existing Some-branch to return `old_identity_id: Some(old_id)` and `old_identity_tier: Some(old_tier)`.
  - Add a new branch at the start of `migrate_identity` for when `mc.identity_instance_id` is `None`:
    1. `let statement = mc.description.as_deref().filter(|d| !d.is_empty()).unwrap_or(mc.title.as_str());`
    2. `if statement.is_empty() { return Err(RepositoryError::InvalidInput { message: "container has no title or description to derive a purpose statement".to_string() }); }`
    3. `let record_title = if mc.title.is_empty() { None } else { Some(mc.title.as_str()) };`
    4. `let now = chrono::Utc::now().to_rfc3339();`
    5. `let record = core_purpose::build_purpose_record(&writer::new_instance_id(), statement, record_title, &now);`
    6. `let new_id = record.instance_id.clone();`
    7. Push `InstanceIndexEntry { instance_id: new_id.clone(), tier: 2, path: "".to_string(), title: None, tags: None }` placeholder — updated in step 8.
    8. Batch: `store.begin_batch()` → call `write_new_record(store, &record, paths::DEFAULT_RECORD_DIR)?` (captures `relative_path`) → update `manifest.instance_index` last entry's path to `relative_path` → `writer::write_manifest(store, &manifest)?` → `container_service::add_container_member(store, &mc.container_id, &new_id)?` → `store.commit_batch()`.
       *Alternative (cleaner): push the `InstanceIndexEntry` with the path AFTER calling `write_new_record` returns the path. Both `InstanceIndexEntry` push and manifest write happen inside the batch.*
    9. Return `MigrateIdentityResult { old_identity_id: None, old_identity_tier: None, new_identity_id: new_id, statement: statement.to_string(), title: record_title.map(str::to_string) }`.

  Note on batch ordering: `write_new_record` internally calls `store.save_instance_json`; when called inside a batch, the write is deferred until `commit_batch()`. Ordering inside the batch closure: (1) `write_new_record`, (2) `write_manifest`, (3) `add_container_member`. This mirrors the Some-branch ordering.

- [ ] Add tests:

  - `migrate_creates_purpose_from_container_title_only` — title="My Repo", description=None; verify `statement = "My Repo"`.
  - `migrate_from_container_sets_identity_instance_id` — verify `manifest.container.identity_instance_id == Some(result.new_identity_id)` after migration.
  - `migrate_from_container_adds_to_members` — verify `new_identity_id` appears in `container.member_instance_ids`.
