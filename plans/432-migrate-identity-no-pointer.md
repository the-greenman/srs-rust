# Plan: Migrate existing repos: root_note_id → identity_instance_id in serialized output history

> Issue: srs-rust#432

## Summary

Repositories created before #424 have no `identityInstanceId` in `manifest.container` and may lack a `com.semanticops.core/purpose` record. The existing `srs repo migrate-identity` command handles repos whose `identityInstanceId` points to a Tier-0 note, but errors with "identityInstanceId is not set" for pre-#424 repos that have no pointer at all. This plan extends the service to handle the `identityInstanceId = None` case by deriving the purpose record from the container's `title`/`description` fields, and also fixes a pre-existing field-ID inconsistency between `migrate_identity_service.rs` and `repository_lifecycle.rs` (the former used wrong hardcoded UUIDs that don't match the canonical core package).

### Phase 2: Extend migrate_identity for identityInstanceId = None

**Goal:** `migrate_identity` creates a purpose record and sets `identityInstanceId` when the container has none, using container title/description as input.

**Agent:** Repository Service Worker

#### Tasks

- [ ] In `crates/srs-repository/src/migrate_identity_service.rs`:
  - Change `MigrateIdentityResult.old_identity_id` from `String` to `Option<String>`.
  - Change `MigrateIdentityResult.old_identity_tier` from `u8` to `Option<u8>`.
  - Add a helper `fn create_purpose_record_for_container(store: &dyn RepositoryStore, statement: &str, title: Option<&str>) -> Result<(String, String), RepositoryError>` (returns `(instance_id, relative_path)`) that:
    - Builds a `Record` with `CORE_PURPOSE_TYPE_*` constants.
    - Computes `relative_path = format!("{dir}/purpose-{}.json", &new_id[..8])`.
    - Writes it via `store.save_instance_json(&relative_path, &record_json)`.
    - Returns `(new_id, relative_path)`.
    - Does NOT do manifest updates or batching — those stay inline in `migrate_identity`.
  - Add a new branch in `migrate_identity` for when `mc.identity_instance_id` is `None`:
    - Let `statement = mc.description.as_deref().filter(|d| !d.is_empty()).unwrap_or(&mc.title)`.
    - If `statement.is_empty()` → `Err(RepositoryError::InvalidInput { message: "container has no title or description to derive a purpose statement" })`.
    - Let `title = if mc.title.is_empty() { None } else { Some(mc.title.as_str()) }`.
    - Call `create_purpose_record_for_container(store, &mc.container_id, statement, title)` → `new_id`.
    - Push `InstanceIndexEntry { instance_id: new_id.clone(), tier: 2, path: relative_path, title: None, tags: None }` to `manifest.instance_index`.
    - Set `manifest.container.as_mut().unwrap().identity_instance_id = Some(new_id.clone())`.
    - Batch: `store.begin_batch()` → `store.save_instance_json(...)` + `writer::write_manifest(store, &manifest)` + `container_service::add_container_member(store, &mc.container_id, &new_id)` → `store.commit_batch()`.
    - Return `MigrateIdentityResult { old_identity_id: None, old_identity_tier: None, new_identity_id: new_id, statement: statement.to_string(), title: title.map(str::to_string) }`.
  - The existing `Some(old_id)` branch stays, but returns `old_identity_id: Some(old_id)` and `old_identity_tier: Some(old_tier)`.
  - Refactor: both the `None` and `Some` branches call the helper to create and write the record (getting back `new_id` and `relative_path`). Do NOT duplicate record-construction logic. Manifest updates and batch operations remain inline in `migrate_identity`, specific to each branch (Some removes old member; None does not).

Note: `mc.description` is `Container.description: Option<String>`. Confirm the field exists in `srs_core::types::container::Container` before using it.

- [ ] Add tests in `migrate_identity_service.rs`:
  - `migrate_creates_purpose_from_container_title_and_description` — container with title + description; verify statement = description, title = container title.
  - `migrate_creates_purpose_from_container_title_only` — container with title but no description; verify statement = title.
  - `migrate_from_container_sets_identity_instance_id` — verify `manifest.container.identity_instance_id` is set after migration.
  - `migrate_from_container_adds_to_members` — verify new record in `container.member_instance_ids`.
  - `migrate_from_container_errors_if_empty_title_and_no_description` — empty title + None description → `InvalidInput`.
  - `migrate_from_container_errors_on_second_run` — run twice; second run returns an error containing "already" (after first run `identity_instance_id` is Some → existing path detects purpose record → errors). Note: this is not idempotency (the second call errors); it is a guard that prevents double-migration.

## Assumptions

- `Container.description` field exists and is `Option<String>` in `srs_core::types::container::Container` (confirmed in code search).
- The canonical field UUIDs are `3b000001…` (statement) and `3b000002…` (title) per `srs/srs/package/core/` (confirmed in spec repo).
- `scaffold_purpose_record` in `repository_lifecycle.rs` is not reused across modules — logic is copied/factored within `migrate_identity_service.rs` to avoid import cycles or breaking the `repository_lifecycle` module's existing private API. Both will be cleaned up when #423 lands.
- Idempotency of the None-case migration relies on the fact that after one run, `identity_instance_id` is set → next run takes the existing Some-branch path → detects "already a purpose record" → returns error. This is correct.
